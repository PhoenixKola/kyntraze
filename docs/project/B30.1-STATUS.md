## Living Combat HUD (what is real)
- **ImageGen (authored):** 7 beast ornaments (flare / comet / still dragons, crimson nine-tail fox, azure phoenix, Riftbound and Voidheart guardians), 4 hero tile frames, 4 hero crest rings, pause crest. Sources and prompts: `art/fx-b30-1/hud/` (+ PROVENANCE.md written by the bridge); keyed to alpha by `process.py`; runtime webp in `public/ui/hud/` (16 files, 527 KB total).
- **Integrated:** per-hero tile frames; per-form accent for all 11 appearances (`data-form`); padlock on locked tiles; edge-detected cosmetics (unavailable -> ready sweep, accepted-cast squeeze, denied-press shake, staggered form-shift sweep + icon crossfade, form-exit settle) computed from the existing per-fighter ability view, not a separate cooldown system; no effects on first mount or while a form shift settles; Overdrive mantle (tail / body / head on separate clocks, own motion signature per beast) shown only while `odT > 0`, outside the row, fades on expiry; compact (co-op P2) shows a single static-ish beast, no body animation. Reduced Effects and `prefers-reduced-motion` keep every state with no animation.
- **Audit fixes:** passive/read-only tiles (Perfect Evasion, co-op P2 row) are no longer `role="button"`, no longer say "click to use", and no longer fall back to `KeyQ`.
- **Retained, not re-authored:** the existing Q/E/R/V/F/G icons (ren_cf_*, sora_cf_*, vex_cf_*, kai_*). The brief asked for new emblems for most slots; I audited and kept them. Per-ability bespoke motion (dragon jaw on E, etc.) is NOT done: cast feedback is a shared strike squeeze + form-coloured ring.
